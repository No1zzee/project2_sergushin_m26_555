# Primitive DB

Учебная консольная база данных на Python. Поддерживает управление таблицами,
CRUD-операции, хранение в JSON, проверку типов, подтверждение удаления,
обработку ошибок, замеры времени и кэширование выборок через замыкание.
Реализация процедурная, без собственных классов и цветного вывода.

## Требования

- Python 3.12 или новее;
- uv;
- Git для клонирования;
- make — для использования Makefile (необязательно для прямых команд uv).

Зависимости приложения: prompt и prettytable. Ruff — зависимость разработки.
Разработка возможна в Windows/Git Bash; для записи asciinema используется
отдельная среда Ubuntu/WSL.

Если установлен make:


Ручная активация окружения для uv run не требуется. При необходимости
в Git Bash с Windows Python используется `source .venv/Scripts/activate`,
а в Ubuntu — `source .venv/bin/activate`. Окружения Windows и Ubuntu
создаются отдельно и не используются совместно.

## Команды

Команды ниже вводятся в запущенном приложении, не в системной оболочке.

```text
create_table users name:str age:int is_active:bool
list_tables
insert into users values ("Sergei", 28, true)
select from users
select from users where age = 28
update users set age = 29 where name = "Sergei"
info users
delete from users where ID = 1
```

Для подтверждения удаления введите `y` в появившемся запросе. Затем можно
удалить таблицу командой `drop_table users`, также подтвердив ответом `y`.
`help` показывает справку, `exit` завершает приложение.

`select` без where возвращает все записи. `update` и `delete` требуют where
и обрабатывают все совпадения. Поддерживается одно равенство в where и одно
присваивание в set. Для каждого изменения выводится ID записи.

## Правила данных

- Типы схемы: только `int`, `str`, `bool` в нижнем регистре.
- Команды и ключевые слова пишутся строчными.
- Имена таблиц и столбцов регистрозависимы; используются допустимые Python-
  идентификаторы, например users и user_name.
- Строки заключаются в одинарные или двойные кавычки; пробелы внутри
  сохраняются. Запятая внутри строки не разделяет значения.
- Числа и булевы значения пишутся без кавычек. Булевы допускают любой регистр.
- `"28"` не принимается для int, `"true"` — для bool, а True — для int.
- Все поля обязательны. При insert передаются значения всех столбцов,
  кроме ID, в порядке схемы.
- ID:int добавляется автоматически и не дублируется при явном указании
  в схеме. ID записи равен максимальному существующему ID плюс один,
  для пустой таблицы — 1. Удалённый максимальный ID может использоваться
  повторно. Ручное изменение ID запрещено.

## Декораторы и кэширование

`handle_db_errors` обрабатывает FileNotFoundError, KeyError, ValueError,
ошибки файловой системы и прочие Exception. Ошибка операции возвращает None, поэтому engine не
записывает неудачный результат и не выводит сообщение об успехе.

`confirm_action(action_name)` применяется к drop_table и delete.
Только точный ответ `y` разрешает операцию. Любой другой ответ, пустой ввод,
EOF или Ctrl+C отменяет её. При отсутствии совпадений delete ничего не
удаляет и не запрашивает подтверждение. Некорректные условия и отсутствующие
таблицы отклоняются до запроса подтверждения в интерфейсе.

`log_time` использует time.monotonic и применяется к insert и select:

```text
Функция select выполнилась за 0.001 секунд
```

Фактическое время меняется от запуска к запуску; быстрые операции могут
показывать 0.000. Замер относится к обёрнутой функции, не ко всей команде
с форматированием, чтением и сохранением. Сообщение выводится и при
исключении внутри обёрнутой функции.

`create_cacher()` возвращает cache_result(key, value_func). Словарь находится
в замыкании. Для повторного ключа вычисление не выполняется. Метод clear()
очищает кэш. select использует этот механизм; ключ содержит снимок значений
записей и условие с указанием типов, а результат возвращается копиями словарей.

create_table, drop_table, insert, update и delete очищают кэш при успешном
изменении в памяти. При отмене удаления изменения и очистка не выполняются.
Снимок в ключе также защищает от устаревшего результата при внешнем изменении
данных. Кэш живёт в текущем процессе; JSON продолжает читаться для команд.
Формирование ключа требует обхода данных: это учебное кэширование, а не
индекс или гарантия ускорения каждого запроса.

## Хранение и архитектура

Метаданные: db_meta.json. Данные: data/ в текущей рабочей папке.
Запускайте приложение из одной папки для работы с одной базой.
users хранится в data/users.json; заглавные и не-ASCII символы в именах
файлов кодируются для сохранения регистрозависимости на Windows. Например,
Users хранится в data/~55~sers.json. В командах используются исходные имена.

После подтверждённого удаления таблицы удаляется её файл данных.
Повреждённый JSON не подменяется пустыми данными. Запись одного JSON-файла
выполняется через временный файл; многопроцессные транзакции не реализованы.
Данные и виртуальное окружение исключены из Git.

```text
src/primitive_db/
├── __init__.py
├── main.py          — точка входа
├── engine.py        — взаимодействие и сохранение результатов
├── core.py          — схема, таблицы, CRUD, использование кэша
├── utils.py         — работа с JSON и файлами
├── parser.py        — разбор команд и литералов
├── decorators.py    — декораторы и фабрика кэша
└── constants.py     — общие настройки и сообщения
```

## Проверка, сборка и установка инструмента

```bash
uv run ruff check .
uv build
uvx twine check dist/*
```

Для версии 0.1.0:

```bash
uv tool install --force dist/primitive_db-0.1.0-py3-none-any.whl
```

При другой версии используйте актуальное имя wheel из dist.
Если uv просит обновить PATH, выполните `uv tool update-shell` и откройте
новый терминал. Вне активного окружения проекта команда `database` запускает
установленный инструмент. Для разработки используйте `uv run database`.
Публикация в PyPI для учебной проверки не требуется.
