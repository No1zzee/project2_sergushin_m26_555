# Primitive DB



Учебный проект на Python: консольное приложение для работы

с примитивной базой данных.



Цель проекта — реализовать создание и удаление таблиц,

добавление, чтение, обновление и удаление записей,

а также сохранение данных в JSON-файлах.



## Текущее состояние



Подготовлена начальная структура Python-пакета.



Реализованы:



- запуск приложения как Python-модуля;

- запуск через команды project и database;

- вывод сообщения DB project is running!.



Операции с таблицами и записями пока не реализованы.



## Требования



- Python 3.12 или новее;

- менеджер проектов и зависимостей uv;

- Git для клонирования репозитория;

- make — при использовании команд Makefile.



Разработка ведётся в Windows с использованием Git Bash.



## Установка



Склонируйте репозиторий и перейдите в его корневую папку.



Установите зависимости и пакет:



```bash

uv sync

```



При необходимости uv загрузит подходящий интерпретатор Python.



## Запуск



Из корневой папки проекта выполните:



```bash

uv run project

```



Дополнительная команда запуска:



```bash

uv run database

```



Запуск как Python-модуля:



```bash

uv run python -m primitive\_db.main

```



На текущем этапе программа выводит:



```text

DB project is running!

```



## Проверка качества кода



Для проверки используется Ruff:



```bash

uv run ruff check .

```



## Сборка пакета



```bash

uv build

```



Собранные файлы появятся в папке dist.



Проверка метаданных собранного пакета:



```bash

uvx twine check dist/\*

```



## Команды Makefile

Они выполняют установку зависимостей, запуск приложения,

## Управление таблицами

Запуск приложения:

```bash
uv run database
```

После запуска команды вводятся внутри приложения.

### Создание таблицы

```text
create_table users name:str age:int is_active:bool
```

Поддерживаемые типы: int, str, bool.

Столбец ID:int автоматически добавляется в начало структуры.
Если ID:int указан пользователем, он не дублируется.

Названия таблиц и столбцов должны быть допустимыми идентификаторами,
например users, products, user_name. Имена чувствительны к регистру.

### Просмотр списка таблиц

```text
list_tables
```

### Удаление таблицы

```text
drop_table users
```

### Справка и выход

```text
help
exit
```



### Хранение метаданных

Имена таблиц и структуры столбцов сохраняются в db_meta.json
в текущей рабочей папке.

Для работы с одной и той же базой запускайте приложение
из одной и той же папки.

Файл db_meta.json исключён из Git.



## CRUD-операции

Запуск из корневой папки проекта:

```bash
uv sync
uv run database
```

В запущенном приложении:

```text
create_table users name:str age:int is_active:bool
insert into users values ("Sergei", 28, true)
select from users
select from users where age = 28
update users set age = 29 where name = "Sergei"
delete from users where ID = 1
info users
drop_table users
exit
```

Все поля обязательны. Значения перечисляются в порядке столбцов схемы,
без ID. ID назначается автоматически: максимальный ID среди существующих
записей плюс один; в пустой таблице — 1. После удаления максимального ID
его номер может использоваться повторно. Ручное изменение ID запрещено.

`select` без `where` возвращает все записи. `update` и `delete` требуют
`where` и обрабатывают все совпавшие записи. Для каждой изменённой или
удалённой записи выводится сообщение с её ID. Если совпадений нет,
выводится соответствующее сообщение. Для `set` и `where` поддерживается
по одному выражению равенства, как в синтаксисе задания; AND/OR и несколько
присваиваний не поддерживаются.

Правила значений:

- Строки — в одинарных или двойных кавычках: `"Sergei"`, `'Sergei'`.
- Целые числа — без кавычек: `28`, `-5`.
- Булевы — без кавычек, в любом регистре: `true`, `True`, `FALSE`.
- Типы схемы — только `int`, `str`, `bool` в нижнем регистре.
- Имена таблиц и столбцов чувствительны к регистру.
- Команды и ключевые слова — только в нижнем регистре.
- Строка `"28"` не принимается для столбца `int`.
- Пробелы вне значений допускаются; внутри кавычек сохраняются.
- Запятая внутри кавычек — часть строки, например `"Ivanov, Ivan"`.
- В строке можно экранировать её кавычку и обратную косую черту.
- Все условия и присваивания проверяются по схеме даже в пустой таблице.

Метаданные находятся в `db_meta.json`, записи — в папке `data/` текущей
рабочей директории. Запускайте приложение из одной папки, чтобы работать
с одной базой. `users` хранится в `data/users.json`. Для сохранения различия
регистра на Windows заглавные и не-ASCII символы в имени файла кодируются:
например, `Users` хранится в `data/~55~sers.json`. В командах используются
исходные имена. Зарезервированные имена файлов Windows также кодируются.

Удаление таблицы удаляет и её файл данных. Повторное создание начинает
пустую таблицу. Повреждённый JSON вызывает ошибку и не заменяется пустыми
данными. Запись одного JSON-файла выполняется через временный файл.
Одновременная работа нескольких процессов и транзакции не реализованы.

Проверка и сборка:

```bash
uv run ruff check .
uv build
uvx twine check dist/*
```
